## 修正：投影片「[lib]」失敗——程式庫改放自己這邊（v2026.1115.2350）
- 手機回報「投影片做不出來 [lib]」：做投影片用的 PptxGenJS 程式庫原本從外部 CDN（cdnjs）下載，這支手機的網路連不到。
- 修法：把 PptxGenJS 3.12.0 一份放進本站（pptxgen.bundle.js，約 470KB），先從本站載入，失敗才試外部 CDN；每個來源都會重試。第一次做投影片時才會下載，之後瀏覽器會留存。
- 圖表與關係圖（Mermaid）、PDF 讀取（pdf.js）仍從外部 CDN 載入，如果也連不到，需要同樣處理，請回報。

## 修正：投影片、字卡仍做不出來（v2026.1115.2300）
- 手機實測回報：投影片還是失敗、字卡是空的。這次用真正的 PptxGenJS 3.12 在瀏覽器跑過，找到原因：小智回來的 JSON 只要有一張投影片的「要點」不是陣列（例如單一字串或空值），整份就當掉；字卡則是小智用了別的欄位名稱（如 front／back、term／definition）就整組被濾掉。
- 修法：投影片與測驗字卡的資料先「正規化」——要點字串自動拆行、缺欄位補空白、欄位別名（title／points／verse、front／back、term／definition、answer 為字母或選項文字）都認得；測驗與字卡要兩者都有才算成功，不夠就再問一次，仍不全則用現有的部分。投影片失敗時，提示後面會加一個短代碼（例如 [http 500]），方便回報原因。

## 修正：文章頁、投影片、測驗與字卡常「做不出來」（v2026.1115.2230）
- 原因推測（手機訊號弱時最明顯）：這幾項都要小智一次產生一大段 JSON，原本用「快速」模型、沒有逾時也不重試，回來的內容只要多一個換行、被截斷或夾了說明文字，就整個失敗。
- 修法：長內容（1200 字元以上輸出）改用「深入」模型；每次請求有逾時（45／90 秒）並自動重試最多 3 次；回來的 JSON 會自動修復（去掉 ``` 圍欄、字串裡的換行、多餘逗號、被截斷時補齊括號）；仍讀不出來時，再用更嚴格的提示重問一次；PptxGenJS 這類外部程式庫載入失敗也會重試。套用在：做成文章頁、做成講道投影片、測驗與字卡；聽講筆記整理、Word 檔等長輸出也一起受益。
