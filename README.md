## 診斷：分段生成失敗時顯示哪一步、回了幾個字（v2026.1116.0740）
- 回報：手機上投影片仍顯示 `[cut]`（可能還是舊版，也可能分段呼叫真的被截斷）。
- 新版失敗時提示會寫成 `c18 plan:cut:0c / cut`：`c18` 代表是分段新程式；`plan` 是失敗的步驟；`cut` 是被截斷（`bad` 是讀不懂）；`0c` 是那次回了幾個字。若是 0 個字就代表額度被思考吃光，需要調整 Worker。

## 修正：小工具、投影片、測驗、文章頁改成「分段生成」，不再被長度上限截斷（v2026.1116.0720）
- 回報：小工具仍顯示「內容太長沒做完」，投影片只做出標題頁加一頁。原因：伺服器把每次回答壓在約 1024 個 token，叫小智「接著寫」並不可靠。
- 新做法：每次只要小智寫一小塊，一塊都遠低於上限，再由頁面組合。
  - 投影片：先列大綱（標題＋7–9 張的標題），再每張投影片各問一次（同時 3 張並行），任何一張失敗會自動重試一次較短的；至少成功一半以上才輸出。
  - 測驗與卡片：前半 3 題、後半 2 題、6 張卡片，共 3 次小呼叫。
  - 文章頁：先列標題與小標，再每個小段落各寫一次，另外一次抓經文。
  - 小工具：分兩段——先寫畫面與樣式，再寫程式（會看到前一段的欄位名稱）；修改也一樣。兩段各自被截斷時，自動改要求更短版本重試。
- 分段全部失敗時，仍會退回原本的一次生成（可能得到不完整但可用的內容）。
- 無頭瀏覽器測試（模擬 1024 上限：回答超過 1200 字就截斷並回報 max_tokens）：七種語言的投影片都做出 9 張（標題頁＋8 張），文章頁三個小節、測驗＋卡片、小工具兩段組合後可在隔離框內運作並可修改；某一塊第一次被截斷時會自動重試成功。所有請求的 max_tokens 都不超過 1024（小工具兩段 1000）。沒有在真實手機或真實 Worker 上測試。
- 可選：若主耀日後把 Worker 的 `Math.min(…,1024)` 上限調高，內容可以更豐富，但費用會增加，需要自己在 Cloudflare 重新部署。

## 修正：小智「連不上 (empty)」自動備援；長輸出自動接續（v2026.1116.0700）
- 回報：問小智出現「小智暫時連不上 (empty)」，重試也一樣。意思是：連線到了伺服器，但回來的串流裡沒有任何文字（原因可能是模型回了空內容、只回了「思考」、或伺服器回了錯誤卻用 200 狀態碼）。以前程式只重試同一個做法，所以一直失敗，而且看不到原因。
- 現在失敗時（沒有任何文字出來之前）會依序自動改試：① 非串流同一個模型 → ② 換另一個模型（快速↔深入）→ ③ 備用舊模型（claude-haiku-4-5／claude-sonnet-4-6，Worker 白名單內）。任何一步成功就正常顯示答案（也會繼續接續被截斷的回答）。
- 全部失敗時，錯誤訊息會顯示每一步的原因（例如 `empty › max_tokens+thinking › …`、或伺服器回的錯誤文字如 credit balance too low），方便判斷是金鑰額度、模型停用、或其他問題。完整原因也存在 `window.__xzdiag`。
- 發現：Worker（bible/worker/xiaozhi-proxy.js）把 `max_tokens` 上限壓在 1024。所以長回答、投影片、測驗、小工具一次只能寫約 1024 個 token 就被截斷。App 端現在把所有「被截斷」都改成「請模型從中斷處接著寫」（回答、JSON、小工具），不需要改 Worker 也能完整；若要更快，可把 Worker 的上限調高（花費與速度由主耀決定）。
- 無頭瀏覽器測試：空串流→非串流備援、需要舊模型才成功、全部失敗顯示原因、200 但帶錯誤文字、截斷的 JSON 接續成功。沒有連到真實 Worker（沙盒連不上），不知道這次 (empty) 的真正原因，需要手機實測並看錯誤訊息。
